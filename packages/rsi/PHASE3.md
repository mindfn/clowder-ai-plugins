# RSI 插件第三阶段：夜里自己往下走（对齐稿，2026-11-18）

目标：一个评估项一晚能连续推进多轮。

- 执行出错时，有人当场修，修完插件自己重跑。
- 结论出来后，按声明时定的规则自己往下走。
- 白天看到的是按记录生成的夜间总结，只有要人定的事才推给人。

也就是让 FLOW §1.5「代码推进，agent 和人只做判断」在夜里真正成立。

## 分工（不变）

- **插件管流程，同时是一个通用的调度器。** 它按计划在对的时间拉起成员登记的命令，用宿主系统的 shell，和 Host 拉起 CLI 一样；记录输出、耗时和失败，到点停止。命令里是什么，插件不关心。
- **成员负责具体的事。** 第 3 步把项目的脚本封装成这些命令；出错时修；给结论、给方向、出版本。

## 现状：为什么和单个 agent 没区别

- **一晚只能跑一个周期。** 每个周期出结论后都等人选方向，下一周期被 `r.report && !r.decision` 挡住。FLOW §1.5 写了「没回应：到点用默认 / 照旧」，但没有实现。
- **执行失败只能等人。** 失败自动重试一次后，整个周期算证据不足，要等人选「修执行」方向。FLOW §1.5 写了「代码处理不了的失败才派给执行成员看」，但没有实现。
- **所有方向都要人选。** FLOW §3「声明范围内调变量，agent 自定」没有实现。
- **失败时拿不到错误特征。** 执行器登记了 `analyze`，但插件从来不跑，成员只能看日志尾巴。

结果：夜里能做的事，单个 agent 一个人一直做反而更快；评估、分析、记录这些多 agent 的长处，在夜里用不上。

## 要做的（通用，不针对某个项目）

### 1. 失败直接派给治理执行成员（修复环）（alpha.54 已做）

- **派给谁。** 一次运行在自动重试后仍失败时，插件跑 `analyze` 抽出错误特征，然后把「哪一组、哪一步、错误特征、日志尾巴」派给治理执行成员。
- **怎么修。** 成员改项目、提交，调 `rsi.version`（kind 是执行修复：直接成为默认，不和旧版本比，沿用原来的变量）。插件在时段内立刻重跑这个周期，不等评估、分析，也不等人。
- **什么时候停。** 以下任一情况就停，停下后照常交评估成员下结论，再等人：
  - 本晚修复次数用完（声明时定，默认 5 次）；
  - 同一错误特征连续出现 3 次；
  - 成员说修不了。
- **每次修复都是一个版本、一次提交**，版本树上可以回退。

### 2. 审批按方向类别（声明时讨论定）

- **声明里加一项「夜里哪些可以自己定」。** 默认按 FLOW §3：
  - 可以自己定：声明范围内调变量、执行修复；
  - 要人批：改实验本身的代码、改指标、改目标、改执行方式。
- **自动采纳的条件。** 结论出来后，分析成员意见一致（只有一位时，看他的第一方向），并且第一方向属于可以自己定的类别：夜里直接采纳，治理执行成员出版本，下一周期接着跑。
- **其余情况等人。** 意见不一致，或类别要人批，都等人决定。

### 3. 没人回应：到点照旧（alpha.53 已做）

时段内，一个结论等人决定超过 30 分钟，就按默认往下走：

- 有候选：复验候选；
- 没有候选：用当前默认版本、换新种子再跑一轮。这样多一份证据，不改任何东西。

### 4. 早上的夜间总结

时段结束时发一张卡，内容全部从记录生成，不靠成员自述：

- 跑了几轮，每轮的结论；
- 自动采纳了什么（版本、提交、理由）；
- 修了哪些失败（错误特征 → 修复版本）；
- 现在卡在哪；
- 等你定的事。

### 5. 调度补齐（通用）

- **异步任务**：加总超时，查询间隔可以配置；超时或失败后跑 `cancel` 清理。
- **运行时段**：时段外不再开新的运行；时段结束时，停掉正在跑的。
- **采集**：拿到本次运行的起止时间，好从累积的日志里切出这一次。
- **拉起命令**：用宿主系统的 shell（Windows 用 cmd）。已在 alpha.52 完成。

### 6. 判定口径能写「不比对照差」

判定口径在声明时讨论生成。除了现在的「比对照至少好 minDelta 才算赢」，还要能写「不比对照差超过 X 就算过」（非劣效）。

### 7. 存储按评估项分开

一晚多轮，会更快撞到每个用户 1 MB 的上限。

## 怎么算比单 agent 好

- 一晚能推进的有效轮数，不少于单 agent。
- 每一轮的结论都能对回插件采到的数，而且由另一个模型的评估成员核对，不靠修复成员怎么说。
- 早上的总结，人不需要再翻日志去核对。

## 验证

在 `rsi-demo-arith` 上加一个模拟的远程执行器：

- 提交时返回 job id；
- 查询时会返回运行中、完成、失败或卡住；
- 按配置注入几类问题：要改代码才能过的错误，以及卡住、需要超时的任务。

然后跑一晚，看这几件事是否都按规则走：修复环、到点照旧、自动采纳、夜间总结卡、超时清理。
