# M0 Standalone Runtime / Standard I/O Plan (P-1 remainder)

> **Status: draft R49 — maintainer R9 exact-body audit (comment 5016029437, REQUEST_CHANGES on `95e4e99c…`) absorbed: the R8 value-routing fix was confirmed; R9's remaining P1 — a malformed response-shaped frame (e.g. `{"jsonrpc":"2.0","result":null}`) was dual-routed by T-D and T-H — is fixed this revision by **response-candidate precedence**: after W0, an object with no `method` and ≥1 of `result`/`error` enters the response lane before any Request/Notification or ID routing — valid correlated responses settle silently (T-L accept), every malformed/unmatched candidate closes (T-H); T-D narrows to idless non-response-candidate non-Requests; method-bearing `result`/`error` extras stay T-F/T-K. Close/accept classes (T-A/T-C/T-E/T-H/T-I/T-K + T-J/T-L) remain excluded from the public union/proofs; eleven variants unchanged. Earlier: R7 Notification partition (T-J/T-K), R6 disposition table, R32 M7/dual-arms.**

**Goal:** Complete the plugins-side M0 vertical slice (roadmap PR-4 "P-1"): a real child-process standalone runtime speaking the standard I/O wire protocol, one shared SDK client that first- and third-party plugins use identically (P14), and the adversarial matrix executed with SDK-surface operations over the real transport — with every wire-level word contract-owned before any runtime consumes it.

**Position in roadmap:** P-2 (merged PR #6, `f52e820`) was slice-0: the 16+2 signed behavior cases execute in-process. This plan covers the remainder as revertible slices **P-1a (wire contract delta, mechanizing the #1165-corrected shape) → P-1b (shared wire-client core + test-host harness, dual-transport oracle) → P-1c (SDK author surface)**. M0 gate additionally requires kernel-side K-2 (Host Broker MVP, maintainer).

| Structure | Fields | Authority |

### Framing (accepted with constraints)

JSON-RPC 2.0 over UTF-8 NDJSON; one non-batch object per LF-delimited frame; stdout is protocol-only (logs → stderr); **v0 compact encoding profile (canonical, #1168 merged `d606aab`): compact UTF-8 JSON, no BOM, no insignificant whitespace, LF terminator; every inbound string token must byte-equal the production compact encoder's serialization of its parsed value (so alternate `\u` spellings are rejected); non-control Unicode encoded directly as UTF-8; required JSON escaping counts toward the budget**; batch arrays, compression, blank frames, invalid UTF-8, trailing non-whitespace all rejected in v0; **`maxFrameBytes = 1_048_576`** counted on raw UTF-8 bytes excluding LF (4× beta.2's 262,144-byte element-payload ceiling); an unterminated frame crossing the ceiling → stop buffering, close connection — **the decoder ceiling is the last fail-closed defense, never the normal rejection path for schema-valid values** (inbound checked pre-dispatch, outbound checked pre-write-queue); oversized domain results are **never** transport-split — method schemas paginate below the ceiling or negotiate a later wireVersion.

**R31 pre-parse closure on top of that merged profile:** the scanner decodes every member name and string value only far enough to require `UnicodeScalarString` (no isolated UTF-16 high/low surrogate code unit) before canonical-token comparison; every object rejects a repeated canonical-decoded member name at the same object depth before `JSON.parse`/schema validation; every numeric token is checked against its path's canonical numeric profile before parsed-value validation. Object member order is deliberately unconstrained because it does not change semantics or encoded length; whole-frame `JSON.stringify(parsed) === raw` is therefore **not** the rule.

### Package digest

Exactly **one** canonical `sha512-<base64>` SRI token over the exact staged archive bytes, for every package source: ASCII string length exactly **95**, pattern `^sha512-[A-Za-z0-9+/]{85}[AQgw]==$`, compact-JSON encoded length exactly **97** bytes including quotes. The final data character restriction is the RFC 4648 zero-pad-bit rule for a 64-byte SHA-512 digest; decode → re-encode equality is the equivalent conformance oracle. npm artifacts additionally pass registry integrity; local packages become an exact archive before install. An unpacked-tree normalization is not a second digest truth.

### Call meta & settlement identity (replaces every earlier `operationId` proposal)

```
JSON-RPC id = requestId          attempt correlation ONLY
params.meta.deadlineUnixMs       Host-capped absolute deadline
params.input                     method-owned schema
registry.settlementKeySource     authoritative domain field/composite or "none"
```

There is **no generic wire `operationId`**. The Broker *extracts* the settlement key from input, never duplicates it. Retry: new requestId + same settlement key + same input → converges on the existing terminal/in-flight result; same key + different input → conflict. Rows marked `none` must prove at-least-once replay safety and monotonic cursor advancement before publication.

**Registry-wide byte-proof invariant (canonical per #1168 merged `d606aab` — no longer ★; conditions semantically pinned, source of literal truth = the merged doc):** the contract schema and generator own **one `wireBounds` truth** whose frame cap is v0 `maxFrameBytes`. A row may be marked ready only when all four canonical conditions are generated and mechanically checked: ① every variable-length request/result/notification/acknowledgement/public-error field has a structural limit **plus an exact UTF-8/JSON byte validator** (canonical ruling: **JSON Schema `maxLength` alone is not a byte proof — it counts characters, not encoded bytes**); ② the row declares `maxEncodedRequestBytes`/`maxEncodedResultBytes`/`maxEncodedErrorBytes`, each ≤ `maxFrameBytes` under the v0 compact profile incl. shared `CallMeta` and escaping; ③ collection assemblers admit an item only if the encoded page stays within the row's result budget, **preserve continuation/watermark state when the next item does not fit**, and prove one individually valid item fits; ④ request validation + row proofs are checked **before authorization-visible business dispatch**, dynamic page assembly completes within budget **before advancing any delivered watermark, callback lease, or settlement state**, and the final encoded frame is re-checked **before write-queue mutation** — an over-budget value is a contract violation, never a partially emitted success. Proof coverage spans requestId, plugin/package/version/session identifiers, `bindingNonce`, message/thread/subscription identifiers, handles, cursors, `deliveryId`, callback acknowledgements, and closed public error data. **A method name may be reserved without proof, but cannot be published or advertised as ready.** Conformance adds: max-boundary frames in all three encodings, +1-byte oversize rejection, pagination continuation, and zero-side-effect oversize rejection.

**Cross-cutting progress invariant (R2, rows 6/8/9):** a response may authorize cursor, lease, or settlement progress **only through a Host-minted entitlement produced after both causal completeness and the final wire-byte proof**; any stale, capture, or proof failure emits no entitlement and mutates no progress state.

**Public bounds vs internal budgets (R3-P1#5 — supersedes every earlier "provisional / adjusted without ceremony" phrasing):** a **public schema bound** (any request/result/error field cap, enum, grammar rule, or page limit visible in the contract schema) is fixed by co-sign; a proof-driven change to a public bound **reopens the shape gate as a reviewed contract delta** and never inherits the co-sign automatically. **Internal generator/assembler budgets** (`pageByteBudget`, `maxSerializedItemBytes`, per-row `maxEncoded{Request,Result,Error}Bytes` values) are generator-derived and may change without touching the public schema, provided every public bound still holds. Issued entitlements bind an **immutable shape/budget digest** — a budget change invalidates continuation across it rather than silently altering replay output.

**Reservation-only lifecycle (R2 D0 = Option A):** the co-sign covers the closed field-level/reservation shape and authorizes only the contract PR; **every row is `ready=false`, unpublished, and unadvertised** until its exact UTF-8/JSON validators, generated `maxEncoded{Request,Result,Error}Bytes`, N/N+1 raw-byte conformance, and three-stage runtime enforcement pass; proof failure returns as a shape delta and never silently raises the v0 cap.

**Contract-minted opaque tokens in handshake/lifecycle rows:** `bindingNonce` (rows 1–2) and the row-11 ping `nonce` are strings, minLength 1, maxLength 512. Their exact compact-JSON leaf validator first requires `UnicodeScalarString`, then inbound raw-token byte equality with the production compact encoder, then `utf8(JSON.stringify(value)).length <= 3_074` bytes (`6 × 512 + 2`, including quotes); full-frame proofs use those same canonical bytes. The co-signed authority direction and semantics are unchanged.

### Outer JSON-RPC envelope (closed — the RequestId owner value landed in R4-intake [5005069362](https://github.com/zts212653/clowder-ai/issues/1165#issuecomment-5005069362); R23/R24/R26 — the frame level the DTO caps cannot see)

Without a contract-owned outer envelope, a sub-frame request with an enormous `id` or numeric deadline evades every method DTO cap while the decoder ceiling stays the last defense — which canonical `d606aab` forbids as a normal rejection path, and whose proof coverage explicitly spans `requestId`. The envelope family is therefore contract-owned and closed (`additionalProperties: false`, all listed members required):

- **`WireRequest`** = `{ jsonrpc: "2.0" (const), id: RequestId, method: <the 12-name enum, direction-checked against the registry>, params: { meta: CallMeta, input: <the row's input schema> } (closed, exactly two keys) }`.
- **`WireNotification`** = same shape **without `id`** — legal only for registry rows declared as notifications (row 10 `host.grants.changed`). An object carrying an `id` is a Request (a notification-only method with an `id` is T-F: `Invalid Request`, id echoed). A canonical **idless** object first passes the response-candidate precedence (no `method` + `result`/`error` → **T-H close**, R44/R45); otherwise it splits per §4.1 (R39, maintainer R7): structurally valid ⇒ it **is a Notification** and never receives a Response — legal row-10 → **T-J accept**; request-only/unknown/direction-invalid method, invalid params, or any idless envelope-shape failure (missing/extra `params`/outer members) → **T-K close, no response, zero dispatch**; structurally invalid (missing/invalid `jsonrpc`/`method`) ⇒ not a Request object at all → **T-D (`Invalid Request`, `id: null`)**.
- **`WireSuccessResponse`** = `{ jsonrpc: "2.0" (const), id: RequestId (byte-equal echo of the originating request `id`), result: <the row's result schema> }` — no `error` member.
- **`WireErrorResponse`** is a closed `oneOf`: application errors are `{ jsonrpc: "2.0", id: RequestId, error: { code, message, data } }`; JSON-RPC standard errors are `{ jsonrpc: "2.0", id: RequestId | null, error: { code, message } }` with no `data` member. Both variants forbid `result` and additional members. **A valid, uniquely extracted, profile-compliant `id` must be echoed byte-for-byte on every standard error that has one — including `Invalid Request`; `id: null` is restricted to the arms where id detection truly failed** (Parse error; the Invalid-Request no-usable-id arm, narrowed by R35/R39 to exactly **a canonical idless object that is not a valid Request object at all** (missing/invalid `jsonrpc`/`method`) — a structurally valid idless object is a **Notification** and takes T-J/T-K with no Response ever (§4.1, R39); the former "malformed/ambiguous/unparseable" readings are re-assigned one class each by the pre-dispatch disposition table below: a non-canonical or duplicated id token closes at W0 (T-C), and a detected id whose value is outside the profile closes with no response (T-E)) per JSON-RPC 2.0 §5 (response id matches request id; `null` only when detection failed) — never a Host choice on a valid request (R32, maintainer R5 P1-2), never a disguise for a detected-but-profile-invalid value (R35, maintainer R6 P1), never a reply to a Notification (R39, maintainer R7 P1), and never a reply to a response candidate — an inbound no-`method` object carrying `result`/`error` is classified by the response-candidate precedence before any Request/Notification routing — valid-correlated → T-L silent settle, every other candidate → T-H close (R44/R46). Result/error mutual exclusivity and per-error member sets are structural, not runtime conventions.
- **`RequestId` — RESOLVED, maintainer value verbatim (R4-intake 5005069362):** `type: string`, `minLength 1`, `maxLength 128`, `pattern ^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$`, raw UTF-8 byte length 1..128. The ASCII value grammar plus canonical raw-token equality makes the token exactly 3..130 bytes including quotes; an alternate spelling such as `"\u0061"` is rejected before dispatch rather than normalized to `"a"`. **String-only: numeric, `null`, non-string, over-length, and grammar-invalid request IDs are protocol violations before dispatch with one deterministic disposition — connection close with no response (T-E; R35, maintainer R6 P1)** — response-side `id: null` exists only in the true detection-failure arms (T-B parse error / T-D id-absent). The issuer keeps IDs **unique among in-flight requests within one `brokerSessionId`**; an in-flight collision fails before dispatch as **T-I close, no response** (R37 — an error echoed under a colliding id is indistinguishable from the in-flight request's terminal response and could falsely settle it; the in-flight attempt recovers through settlement ledgers after reconnect). **A retry is a new attempt and uses a fresh RequestId** (attempt-only, non-authoritative for settlement — canonical role preserved). Success/error responses echo the originating valid ID **byte-for-byte**. Generated full-frame proofs include the surrounding JSON quotes and the outer envelope.
- **`deadlineUnixMs` wire numeric grammar (raw-token level, not parsed-value — R24, FC-R23-1):** the raw JSON lexeme must match canonical decimal digits `0|[1-9][0-9]*` — no sign, no decimal point, **no exponent**, no leading zeros — with raw token length ≤ 16 characters (the decimal digit count of 2^53 − 1, a derived structural fact, not a policy number), validated **pre-parse/pre-dispatch**; exponent-padding (`1e0…01`) and every other non-canonical numeric encoding is rejected before dispatch. The parsed value must additionally be a positive integer ≤ 2^53 − 1. The **operational Host deadline cap policy stays K-2's**.
- The outer members (`jsonrpc`, `id` incl. its JSON quotes, `method`, braces and separators) are **included in every generated `maxEncoded{Request,Result,Error}Bytes` proof** (canonical: proofs include shared `CallMeta` and cover `requestId`; the RequestId value above is now fixed), with mutation and N/N+1 conformance cases proving oversize/malformed-envelope/non-canonical-string/non-canonical-numeric/duplicate-member/non-scalar-string/non-string-id rejection **before authorization-visible dispatch**. Duplicate-member fixtures cover the outer envelope, a nested closed DTO, and a nested frozen-open payload; numeric-alias fixtures cover both object and array positions inside M2; lone high- and low-surrogate fixtures cover member names, bounded string values, and object/array positions inside open payloads. Each mutation case additionally asserts its disposition-table outcome: T-C/T-E classes prove **zero authorization-visible dispatch and zero response bytes before connection close**; T-B/T-D/T-F/T-G classes prove the exact closed error variant and id arm (R35).

**Pre-dispatch disposition table (R35 — absorbs maintainer R6 [5015117839](https://github.com/zts212653/clowder-ai/issues/1165#issuecomment-5015117839); governing invariant stated once):**

> Every raw-frame/profile/request rejection class has exactly one deterministic transport disposition: either a closed, byte-proved JSON-RPC error whose ID semantics are valid for that class, or connection close with no response. No failure class may fall between those two sets.

Decision rule: a failure of **frame canonicality or id-profile trust** closes the connection — nothing can be safely echoed, and §5 forbids `null` once detection succeeded; a failure **above a canonical frame with trustworthy id semantics** answers with the closed, byte-proved error whose id arm matches (byte-equal echo, or `null` only for true detection failure). The strict-profile route for detectable-but-profile-invalid ids is the maintainer-recommended R6 option; every close-class is **excluded from the public error union and its byte proofs by construction**.

**State partition (R39/R44 — the table is the projection of this product, per the maintainer's R7 state-model requirement, not a list of patched examples):** outcome derives from ① frame/parse canonicality (T-A/T-B/T-C gate first), ② **response-candidate precedence (R44, maintainer R9): an object with no `method` and at least one of `result`/`error` is a response candidate and enters the **response lane** before any Request/Notification or ID-profile routing — a candidate that is **valid for its specific in-flight request** — the correlated row's result/error schema plus every cross-frame semantic oracle (row-9 `deliveryId` byte-equality included), with a profile-valid `id` byte-matching an in-flight outbound request — **settles that call silently (T-L accept, no response emitted)**; every other candidate — missing/invalid id, malformed members, `result`+`error` together, failed correlation, or any per-row/cross-frame validity failure — closes on T-H; a **method-bearing** object stays on the Request/Notification lane, where an extra `result`/`error` member is an envelope-shape violation (T-F for a profile-valid-id Request, T-K for an idless Notification), ③ **Request-object structural validity** (`jsonrpc` const + `method` string present), ④ **ID state** (absent | profile-valid | detectable-profile-invalid | ambiguous/untrusted), ⑤ **notification eligibility and method direction**, ⑥ invocation/schema validity. A canonical **idless non-response-candidate** object splits by ③: structurally valid ⇒ it **is a JSON-RPC Notification (§4.1)**; structurally invalid ⇒ it is not a Request object at all and no ID is available. The added JSON-RPC rule is adopted verbatim: **once a canonical object is classified as a Notification, no JSON-RPC Response is emitted for any downstream method/params/profile rejection.**

**Validator profiles used by the table:**

- `UnicodeScalarString` means the decoded member name/string value consists only of Unicode scalar values (`U+0000..D7FF` or `U+E000..10FFFF`): the pre-parse scanner rejects any unpaired high or low UTF-16 surrogate **before** canonical-token comparison. A valid surrogate pair denotes one scalar; lone `"\ud800"`/`"\udc00"` tokens reject even though JavaScript can parse and re-serialize them byte-identically.
- `CanonicalStringToken` means the inbound raw string lexeme must byte-equal `JSON.stringify(parsedValue)` from the production compact encoder **before** schema/parsed-value validation; outbound uses that same encoder. This rejects alternate `\u` spellings (for example `"\u0061"` versus `"a"`) and makes the measured canonical token the only wire representation. It is applied only after `UnicodeScalarString`; equality alone is not a scalar-value proof.
- `CanonicalNumberToken` means an M2 raw numeric lexeme must byte-equal the production compact encoder's scalar serialization of the same parsed **finite** numeric value, recursively at every object/array depth before schema validation. It rejects aliases such as `1e2` for `100`, `-0` for `0`, exponent padding, and values that parse outside the encoder's finite numeric domain.
- `JSONString(N)` means `UnicodeScalarString` + `CanonicalStringToken` + schema `maxLength: N` measured in Unicode code points and `utf8(JSON.stringify(value)).length <= 6N + 2` (quotes included; six bytes/code point is the JSON escaping worst case). The generated full-frame proof uses the same production encoder and actual bytes, not this upper bound as a second encoder.
- `ASCII(N)` means `UnicodeScalarString` + `CanonicalStringToken` plus an ASCII grammar of at most `N` characters and exact compact-JSON leaf size at most `N + 2` bytes including quotes.
- `WireUInt53(min,max)` is the single contract-owned numeric profile: raw JSON lexeme `0|[1-9][0-9]{0,15}`, length 1..16, no sign/point/exponent/leading zero, checked before parse; parsed value must satisfy `Number.isSafeInteger`, `min <= value <= max`, where `max <= 9_007_199_254_740_991`. A smaller field maximum also shortens its generated raw-token bound.
- `WireIntConst(S)` means the inbound numeric lexeme must byte-equal the signed canonical decimal literal `S` before parse; parsed equality alone is insufficient (`-32090e000…0` is rejected even though it parses to `-32090`).
- `PayloadBytes(E,T)` means the pre-parse raw payload slices are checked at `E` bytes per element and `T` bytes per containing message **after** W0 token/uniqueness acceptance, and the production compact encoder re-checks the parsed/outbound values at the same limits before dispatch/state mutation or write; here `E = 65_536`, `T = 262_144` from T1/T2.
- `CLOSED` means finite shape + exact raw-byte validator + compatible source/admission evidence are all present **as a proposal pending maintainer co-sign**. `RESERVED` means at least one of those is absent; every row reaching it is unclosed and may expose only its reserved registry name, never an advertised request/result schema.

### Row 6 — `messaging.read` bounded paging (semantics/topology resolved at R2; variable-leaf status RESERVED by Matrix M1/M2/M5/M6/M7/I1)

Frozen beta.2 already fixes the read-result discrimination: `SubscriptionReadResponse = SubscriptionNormalResponse | SubscriptionEmptyResponse | SubscriptionStaleResponse`, discriminated by `stale` (`const`) + `ackToken` nullability + `events` cardinality — the `oneOf` plus `const` locks make a fourth combination unrepresentable. **The bounded page family mirrors that frozen discrimination exactly (R19; FC-R18-2 follow-through). R18's three-way `status` enum is withdrawn — it reinvented an already-frozen mechanism, and its "three variants cannot be presence-encoded" rationale was false against the frozen `const`-locked encoding.**

- **`SubscriptionReadPageRequest`** (closed, `additionalProperties: false`, all fields required): `subscriptionId` — string, minLength 1, maxLength 128; `limit` — integer 1..32 (aligned to frozen `events` maxItems 32; a **public schema bound** — change = reviewed shape delta). **No page token** — a read always resumes from Host-side `ackedSequence`; a page token may only be added by a later proposal proving a semantic need (R2).
- **`BoundedSubscriptionReadPageResponse`** — structurally closed `oneOf` (member/discriminator topology), mirroring the frozen variants; contained leaf status is inherited from Matrix M1–M7/I1. Every variant: required = `[events, ackToken, stale]` exactly (frozen mirror), `additionalProperties: false`:
  - *normal*: `{ events: BoundedMessageOutputEvent[] — minItems 1, maxItems 32 (frozen literal), ackToken: string (minLength 1 — frozen `SubscriptionCursor` mirror — maxLength 512), stale: false (const) }` — `ackToken` carries the R2 kind-tagged read-page entitlement; disclosed delta vs frozen: frozen `SubscriptionCursor` was `minLength 1` with no upper bound, the bounded form adds maxLength 512 and the R2 kind tag;
  - *empty*: `{ events: [] (maxItems 0), ackToken: null, stale: false (const) }`;
  - *stale*: `{ events: [] (maxItems 0), ackToken: null, stale: true (const) }` — retention floor has passed the reader; recovery = `messaging.snapshot` catch-up.
  - **Request-relative bound is a conformance oracle, not a schema constraint** (JSON Schema cannot reference another document's `limit`): `events.length ≤ params.input.limit`, executed by the generated validator suite alongside the schema check.
  - **No `lastEmittedSequence` response field** (R18's is removed; FC-R18-2): frozen has none, and the page's last emitted sequence lives inside the entitlement binding — a response copy would be an unconstrained second truth source.

**Host read algorithm (R2 semantics; the empty branch is made explicit — R2 requires the empty variant and the algorithm must be able to produce it, a coherence completion, not a new decision):**
1. A read begins at `A = ackedSequence` (Host state; never caller-supplied).
2. The Host assembles a candidate page under the generated byte budget, stopping before the first non-fitting event, and proves one individually valid event fits.
3. The final retention-floor check runs **after** candidate assembly and byte proof but **before** any response, token, or cursor mutation.
4. If `A < currentFloor - 1` → the *stale* variant: zero events, null token, both cursors unchanged.
5. Else if the candidate page is **empty** → the *empty* variant: null token, **no entitlement minted, no cursor movement**.
6. Else (*normal*) → the Host mints the kind-tagged read-page ack entitlement bound at least to the plugin instance, subscription, the page's last emitted sequence, and the closed shape. Only after the final encoded-page proof may `lastDeliveredSequence` advance monotonically through that sequence.
7. `messaging.ack` validates the entitlement and advances `ackedSequence` monotonically only to its issued sequence; malformed, forged, cross-subscription, wrong-kind, or expired tokens fail before any mutation. Response loss re-reads from acked state.

Row 6 remains structurally `RESERVED` until Matrix M1/M2/M5/M6/M7/I1 close; after that it is still `ready=false` until its generated byte proofs and N/N+1 raw-byte conformance pass (reservation-only lifecycle, D0 = A).

**Fixed invariants (self-decidable, hold under every option):**
- No snapshot page response ever moves a cursor (response-loss safety, FC-12); completion is client-explicit. (Row-6 read pages differ by canonical design: emission advances `lastDeliveredSequence` post-proof, only ack advances `ackedSequence` — see the Row 6 section.)

#### P-1b process-tree Stateful Object Gate (R44 addendum; triggered by cloud R1→R3 landing three consecutive rounds on the same `HarnessChild` isolation/cleanup object)

**Single writer:** the `HarnessChild` internal state machine — every termination trigger (case timeout, protocol/I-O fatal, public `kill()`, natural target exit) funnels through one controller; readers (`receive()`, `waitForExit()`, `stop()`) observe and never mutate.

**States (monotonic, no back-edges):** `spawned → running → terminating → exited → reaped | cleanup-failed`
- `running → terminating`: any of timeout / fatal / kill / natural target exit.
- `terminating → exited`: the **direct target process** has exited — `waitForExit` resolves here (target exit, NOT tree cleanup). Stream `close` (protocol drain, the R2 dual-phase rule) is tracked orthogonally and may complete before or after `exited`; both are prerequisites of `reaped`.
- `exited → reaped`: the whole tree is confirmed gone via bounded existence probes.
- `exited → cleanup-failed`: bounded retries/probes exhausted without confirmation → throw the **public `HarnessCleanupError`** (fail-closed, never silent; the class joins the public export set enforced by the built-boundary guard).

**Invariants:**
- **I1 monotonicity** — states never regress; late triggers are recorded no-ops.
- **I2 hard-kill monotonic finality** — once SIGKILL / the Windows tree-kill is requested, no later path downgrades the signal or soft-re-probes (R2 rule, restated at object level).
- **I3 whole-tree ownership** — POSIX: one process group per case, every kill targets the group. **Windows v0: a sentinel wrapper root** owned by the harness — no native dependency (OS Job Objects deliberately deferred as a later delta needing its own authorization): the wrapper spawns the target, relays target-exit over a control channel, and stays alive as the stable `taskkill /T /F` root until reap is confirmed — the target's own exit can never orphan the tree root, and awaiting `taskkill` (spawn `error` **and** nonzero exit both handled) is a completeness check, not the ownership mechanism.
- **I4 cleanup evidence** — `reaped` requires bounded poll-until-gone probes with a deadline, never one instantaneous existence check.
- **I5 terminal-state table** — kill-utility success / nonzero exit / spawn-error / timeout all converge to exactly one of `reaped` / `cleanup-failed`; no path returns early on the kill utility's exit status alone.

**Answers of record (cloud-R3 gate OQ①–④):** ① Windows v0 ownership primitive = sentinel wrapper root (Job Object deferred); ② `waitForExit` = target exit — three observable phases: `exited` / stream-`close` / `reaped`; ③ terminal states per I5; ④ cleanup failure throws public `HarnessCleanupError`.
